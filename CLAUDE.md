# Infodock — working notes for Claude

`SPEC.md` is the source of truth. Read the sections relevant to your task before writing code, and cite them (`§5.2`) in code comments only where the reason is not obvious. If the spec is wrong or ambiguous, fix the spec in the same commit and say so in the commit message.

`docs/plan.md` tracks milestones and slices. Tick items off as they land and add decisions to its log.

## Layout

```
src/                 Svelte 5 + TypeScript UI (one bundle, routed by window label: src/lib/route.ts)
  lib/bindings/      generated by ts-rs from Rust types; do not edit by hand
src-tauri/           Rust core (crate `infodock`, lib `infodock_lib`)
  src/platform/      OS layer behind traits; Windows code in platform/windows, other OSes get a stub
docs/                plan.md, manual-test.md
tests/fixtures/      shared test fixtures (legacy XML)
```

## Commands

| What | Command |
|---|---|
| Install | `bun install` |
| Frontend build (needed before Rust builds: `frontendDist`) | `bun run build` |
| All lints (eslint, svelte-check, rustfmt, clippy) | `bun run lint` |
| UI tests | `bun run test` |
| Rust tests (also regenerates `src/lib/bindings`) | `cargo test --manifest-path src-tauri/Cargo.toml` |
| Type-check the Windows code from Linux | `bun run check:win` |
| Format Rust | `bun run fmt` |
| Run the app | `bun run tauri dev` (Windows) |

Cloud sessions run on Linux. `check:win` compiles every `#[cfg(windows)]` path without linking; it needs the `x86_64-pc-windows-msvc` target and `llvm-rc` (installed by the SessionStart hook). Real Windows behaviour is verified by CI (`.github/workflows/ci.yml`: clippy, tests, `--ignored` integration tests, NSIS installer and portable exe artifacts) and by the manual checklist in `docs/manual-test.md`.

## Gate before every commit

`bun run lint`, `bun run test`, `cargo test --manifest-path src-tauri/Cargo.toml`, and `bun run check:win` when Rust changed. Commit generated bindings together with the Rust types that produce them.

## Workflow

- Commit straight to `master`, one logical change per commit, and **push after every commit**.
- After pushing, check the CI run; if it is red, fixing it comes before anything else. CI runs only when build inputs change (paths in `ci.yml`); docs-only commits do not trigger it.
- End commit messages with the `Co-Authored-By` trailer the session provides.

## Conventions

- Rust: edition 2024, no `unwrap()`/`expect()` on runtime paths (setup code that cannot continue may `expect`). Command errors serialize as `{ code, message }`. OS calls only inside `platform/`; everything else talks to the `Platform` trait.
- Pure logic (geometry, config merging, formatting) lives in plain functions with unit tests and no OS calls.
- TypeScript strict; Svelte 5 runes only (`$state`, `$derived`, `$props`, `$effect`). Reactive modules are `*.svelte.ts`.
- Every user-visible string goes through `t()` (TS) or `i18n::t()` (Rust); keys live in `src/i18n/en.json`.
- Config `props` store only values that differ from static defaults (SPEC §11.2).
- Coordinates are logical (DIP) in the UI; Rust converts to physical pixels with the monitor scale.
