# M4 review findings

From the M4 close-out review (three clean-context reviewers on `8daf484..674c6fc`, 2026-10-21: skins, the shadow and the bar; export, import and the legacy import; Settings, autostart, the welcome page and the installer). Each finding was checked against the code; findings marked *(to verify)* could not be checked without Windows hardware. Each group is one plan item (S18c–S18e); tick the finding here when it is fixed, with the commit.

## S18c — Skins and the bar

- [x] **High — a small `.zip` can write tens of GB.** *Fixed in `435dd13`: `skin.json` first, then only the files it names.* `bar/skins/install.rs` `install_zip` extracted every top-level entry of up to 1 MB into the staging folder before reading `skin.json`, with no limit on their number; central-directory entries may all point at one deflated block, so a 3.6 MB archive of 65,534 such entries writes about 64 GB on the main thread (the reviewer ran it: 2 GB in 0.9 s for 2,000 entries). Fix: extract `skin.json` first (64 KB at most), then only the files it names, each at most 1 MB.
- [x] **Medium — a stray file in a `.zip` fails the install.** *Fixed in `435dd13`.* Same loop: an entry `skin.json` does not name, compressed with LZMA or encrypted (7-Zip), or named with a character Windows refuses, failed the whole install, against §12.4's "only `skin.json` and the files it names". Fixed by the previous finding's fix.
- [x] **Low — a dragged floating bar keeps its shadow on the old side.** *Fixed in `435dd13`: `nearer_edge` while moving.* `bar/thread.rs` `pointer_moved`: `move_by` did not update the bar's edge, so dragging a floating bar from the lower half to the upper half kept the shadow (and the hairline) facing the old edge until the drop. Fix: the nearer edge follows the moved rect.
- [x] **Low — the band shows at full strength while a floating bar fades in** *(to verify)*. *Fixed in `435dd13`; still to verify on hardware.* A floating bar's rise only fades, so it is never off its place and its band showed at once over a bar still transparent. Fix: no band while the content fades.
- [x] **Low — the last skin stays in memory on the modern bar.** *Fixed in `435dd13`.* `SkinCache` kept the classic skin's bitmaps (0.6 MB at 300 %) and the renderer's upload of them after switching to modern. Fix: forget the skin when the theme has none.
- [x] **Low — the band window is moved every frame** *(to verify)*. *Fixed in `435dd13`; still to verify on hardware.* `platform/windows/band.rs` `follow` called `SetWindowPos` to the same place after every frame (each second with graphs). Fix: move it only when its place changed.

## S18d — Export, import and the legacy import

- [x] **Medium — *Replace* is offered for a file without sensors and empties the bar.** *Fixed in `0080a8a`.* `transfer.rs`: a legacy file holding only unsupported sensors (or a JSON file with only `legacy.unsupported`) asked *Replace* or *Add* for "0 sensors", and *Replace* (the default) left the bar empty; a file whose entries were all skipped said "no sensors" without saying why. Fix: a file without sensors this version can show is not imported, and the message lists what was skipped.
- [x] **Medium — no limit on what an import adds.** *Fixed in `0080a8a`: `Incoming::checked`.* `config/exchange.rs`, `sensors/legacy.rs`: a 3.6 MB file of 200,000 spacers imported them all; the bar, the Layout manager and `config.json` then carry them at every start, far past the memory budget. Fix: a file with more than 500 sensors (with its unsupported ones) is refused with a message (§11.3).
- [x] **Medium — legacy text in other code pages is garbled.** *Fixed in `0080a8a`: `Platform::decode_code_page`.* `config/legacy.rs` `decode`: anything not UTF-8 was read as Windows-1252, ignoring the XML declaration's encoding, so a Croatian (Windows-1250) "Računalo" imported as "Raèunalo" without a warning, and UTF-16 without a byte order mark was refused as holding no layout. Fix: the declared code page, else the system's ANSI code page (`MultiByteToWideChar` through the platform; Windows-1252 where there is none); UTF-16 recognised by its first `<`.
- [x] **Medium — an imported layout opens network paths at once** *(to verify)*. *Fixed in `0080a8a`: `Incoming::network_paths` in the question; still to verify on hardware.* An Image, Shortcut or Folder Menu path such as `\\server\share\a.png` makes the bar connect to that server right after the import, which hands it the user's NTLM credentials; a layout from elsewhere can name any server. Fix: the *Replace* / *Add* question names the network locations the file holds, so the user can cancel before anything connects.
- [x] **Low — report lines have no length limit.** *Fixed in `0080a8a`: `exchange::shown`.* `Warning::InvalidProperty` echoed the raw value, so a 1 MB property became a 1 MB line in the report dialog. Fix: values and names are cut at 80 characters with an ellipsis.
- [x] **Low — a battery index beyond `u32` makes the sensor a placeholder.** *Fixed in `0080a8a`.* `sensors/schema.rs` `check` took any `u64` for the battery field, which the type then failed to read. Fix: only `u32` values pass.
- [x] **Low — an uptime record near `u64::MAX` overflows.** *Fixed in `0080a8a`.* `sensors/uptime.rs` `take_state` added the record step to the stored record (a panic in debug builds, a config write every minute in release). Fix: `saturating_add`; legacy records over 100 years are refused with a warning.
- [x] **Low — JSON files with a UTF-16 byte order mark are refused.** *Fixed in `0080a8a`: `exchange::unicode`.* `exchange::read` read the bytes as UTF-8, so a file re-saved by Windows PowerShell 5 (`>`) was "not a layout". Fix: the same byte order marks as legacy files.
- [x] **Low — legacy power modes are matched with case.** *Fixed in `0080a8a`.* `sensors/legacy.rs`: `Shutdown` or `SLEEP` was "not a valid value", though §11.4 matches selects ignoring case. Fix: compare ignoring case.

## S18e — Settings, autostart and the installer

- [x] **Medium — a cancelled uninstall turns autostart off.** *Fixed in `a3eb76f`: `un.onUninstSuccess`; CI checks the finished uninstall.* `Cargo.toml` `un.Autostart` ran before the template's `Uninstall` section, so the sign-in entry, Task Manager's mark and the AppUserModelID were gone before "Infodock is running" could be cancelled; the app stayed installed, its setting on, and did not start at the next sign-in. Fix: `un.onUninstSuccess`, which runs only after a finished uninstall.
- [x] **Low — running another copy once takes the sign-in entry.** *Fixed in `a3eb76f`: `at_start` with `named_exists`.* `autostart.rs` `at_start` pointed the entry at whichever exe started, so trying the portable exe once (or `cargo run`) and deleting it left nothing starting at sign-in. Fix: the entry is pointed at this exe only when the exe it names is gone (a moved or reinstalled app); the uninstaller removes it only when it names the installed exe. D58 and §10.1 change.
- [x] **Low — the reinstall page's uninstall, then Cancel, leaves a dead sign-in entry.** *Fixed in `a3eb76f`: `.onGUIEnd`; still to verify by hand (`docs/manual-test.md`).* The template runs the old uninstaller with `/P` (which keeps the entry) for *Uninstall before installing*; cancelling the installer afterwards left a `Run` value naming a missing exe. Fix: `.onGUIEnd` removes the entry when it names the install folder's exe and that is missing.
- [x] **Low — the uninstaller leaves `HKCU\Software\jurakovic\Infodock`.** *Fixed in `a3eb76f`; CI checks it.* The template writes the install location there and removes only its language value; CI checked the key under HKLM only. Fix: the uninstaller removes it (and the publisher key when empty), and CI checks HKCU too.
- [x] **Low — CI never checks that the uninstaller removes Task Manager's mark.** *Fixed in `a3eb76f`.* Fix: the mark is set before the first uninstall and checked afterwards.
- [x] **Low — launching Infodock again while the welcome page is open ends the first run.** *Fixed in `a3eb76f`: `settings::activate`.* `app.rs` `activate` opened Settings on General, which left the welcome page and set `meta.firstRunDone` (e.g. the installer's *Run Infodock* and then the desktop shortcut). Fix: a second launch brings an open Settings window to the front without changing its page.
- [x] **Low — the custom image is read on every Settings refresh.** *Fixed in `a3eb76f`: `Gallery::custom_problem`.* `settings/appearance.rs`: `custom_error` read `classic.customSkin` at every config change while Settings was open (each typed character, state saves), also with another skin chosen; a path on an offline share stalled the main thread each time. Fix: the check is kept by path and made only while the skin is `custom`.
- [x] **Low — the gallery keeps a pack's old preview after it is installed again.** *Fixed in `a3eb76f`: listing the folder draws the previews again.* The preview is kept by `skin.json`'s fields, not the tile's pixels, so reinstalling a pack with a new tile under the same `skin.json` showed the old one until Settings was reopened. Fix: installs and removals draw the gallery's previews again.
- [x] **Low — removing the configured pack misses it by case.** *Fixed in `a3eb76f`.* `appearance.rs` `removed` compared `classic.skin` with the folder's name exactly; Windows names ignore case (`ocean` in the config, `Ocean` after an install from `Ocean.zip`), so the setting kept a removed pack. Fix: compare ignoring case.

## Not changed

- **An unreadable custom colour tints packs dark grey** (`bar/theme.rs`): `Settings::sanitize` drops a malformed `background.color` on load and on every patch, so the colour always parses where the theme reads it.
- **Long text values in an imported file** (a 16 MB Text sensor): bounded by the 16 MB file limit and the 500-sensor limit; the file is the user's choice and the Properties form edits it.
- **Export file names** (`transfer.rs` `export_path`) *(to verify)*: a name typed with another extension (`notes.txt`) gets `.infodock.json` after the save dialog's overwrite question; overwriting needs that exact file to exist. The import picker offers all files besides `*.infodock.json`.
- **A non-integer `schema`** (`"2"`, `2.0`): counts as schema 1; no version of Infodock writes one.
- **Images decoded on the bar thread** (a network image stalls the bar): carried over to M5 since M1 S4.
