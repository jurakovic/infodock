# M2 review findings

From the M2 close-out review (three clean-context reviewers on `f8f2bb2..7de0b30`, 2026-10-13: platform, providers and sampler; sensors; bar and Settings). Findings marked *(to verify)* could not be checked without Windows hardware. Each group is one plan item (S15c–S15e); tick the finding here when it is fixed, with the commit.

## S15c — Sampler and platform

- [ ] **High — an offline network drive stalls the sampler.** `platform/windows/disk.rs` `space`, `sampler/mod.rs` `run`: every topic is read in turn on the sampler thread, and `GetDiskFreeSpaceExW` on a mapped drive whose server is away blocks for the SMB timeout. CPU, memory, network and uptime samples stop meanwhile (with a 30 s interval, most of the time); resume reads every topic at once, before the network is back. Fix: read disks on a worker thread; the sampler waits briefly, else uses the newest result at the next tick.
- [ ] **Medium — listing volumes blocks the main and bar threads, under the store lock.** `platform/windows/disk.rs` `volumes` reads every label, network and optical drives included; callers are the Disk Meter form (main thread) and `DiskMeterType::machine_defaults`, which runs inside `store.update` when a Disk Meter is added (bar menu or picker). A mapped drive to an offline server freezes Settings or the bar, and every other store update waits. Fix: read labels only for fixed, removable and RAM drives (network and optical drives are named by kind).
- [ ] **Medium — PDH data with `PDH_CSTATUS_NEW_DATA` is dropped** *(to verify)*. `platform/windows/cpu.rs` compares `CStatus == 0`; status 1 is valid data too. If PDH returns it, the total falls back to processor times (not Task Manager's utility) and the per-processor values vanish. No Windows test covers `WinCpu`. Fix: accept both; an ignored test reading twice.
- [ ] **Low — one bad processor instance shifts the others.** `cpu.rs` `cores`: instances with a bad status are dropped before the list is built, so `core<i>` indexes the wrong processor. Fix: keep every instance at its `(group, number)` position, a bad one as NaN (shown as the total).
- [ ] **Low — baselines outlive their topic.** `sampler/scheduler.rs` drops unsubscribed topics without telling the providers: a CPU topic subscribed again an hour later starts from the hour-old baseline (its first sample is not discarded), and net baselines pile up per adapter ever chosen. Fix: the scheduler reports removed topics; `Providers::forget` drops their baselines.
- [ ] **Low — topics tick on different phases.** `scheduler.rs` `sampled`: each topic's cadence starts when it is first read, so CPU, memory and network (first read at start-up a few hundred ms apart, PDH opening in between) wake the sampler and redraw the bar two or three times a second. Fix: every topic keeps to one grid from the scheduler's first sample.
- [ ] **Low — `per_core_cpu` is always on.** `platform/windows/mod.rs`: with broken performance counters the dual graph is offered but shows only the total (§4.6: the capability means per-processor counters can be read). Fix: decide it once from whether the per-processor counter can be added.
- [ ] **Low — a page file list may include `swapfile.sys`** *(to verify)*. `memory.rs` `parse` counts every entry. Fix: read the entry's name and skip `swapfile.sys`.
- [ ] **Low — the interface table is read through the one-row array.** `platform/windows/net.rs` `interfaces` takes the rows' pointer from `(*table).Table.as_ptr()`, which borrows a `[MIB_IF_ROW2; 1]` and reads past it. Fix: a raw pointer to the field.
- [ ] **Low — stored adapter ids depend on `GUID`'s `Debug` output.** `net.rs` `read`. Fix: format the GUID explicitly in the form `GUID::try_from` parses.
- [ ] **Low — the spec disagrees with itself on failed readings.** §4.4 keeps the previous sample (as the code does); §14.2 asks for `{ error }` samples, `n/a` and a backoff. Fix: the spec says what happens now; error samples and backoff are open (M5 reliability pass).
- [ ] **Low — the first chime or click may raise memory for good** *(to verify)*. `PlaySoundW` and `ShellExecuteExW` load the audio stack and shell DLLs, which CI's memory check never does. Left for the manual check (`docs/manual-test.md` M2).

## S15d — Sensors

- [ ] **High — Uptime never wakes, so its display freezes.** `sensors/uptime.rs` `wake_at` computes the next minute from the real clock, always in the future, so the bar's `wake_at(now) <= now` test never holds; `on_sample` compares with the counted-forward text, so samples rarely redraw either. Also, a catch-up sample up to 60 s old is taken as read on delivery, so the shown minute can step back. Fix: keep the next minute boundary as an instant (moved on in `on_wake`), and carry the reading's time in the sample.
- [ ] **Medium — a graph ignores its own interval when another sensor reads the topic faster.** `bar/sensors.rs` `deliver` hands every broadcast sample to every subscriber; a 5 s CPU graph next to a 1 s meter scrolls once a second. Fix: `deliver` passes a broadcast sample to a sensor only once its own interval has passed since the last one it took (catch-ups always pass); §4.4 says so.
- [ ] **Medium — bar text ignores the locale's decimal separator.** `memory.rs`, `disk.rs`, `network.rs` `measure` format with `Numbers::default()` (§8.6): de-DE shows `5.21 GB` on the bar and `5,21 GB` in the hint. Fix: `LayoutCtx` carries the bar's `Numbers`, kept by the bar from the locale.
- [ ] **Medium — "Click to …" lines ignore Lock (§6.1).** `cpu.rs`, `memory.rs`, `network.rs` always add them; with Lock on and *Alt only*, the hint promises a click that does nothing. Hints are also built with `alt: false`. Fix: `SensorCtx::clicks` (`interact::clicks_allowed`) decides, with the real Alt state.
- [ ] **Medium — changing `dateLocale` or the regional format does not reach Date and Time.** They cache the locale until a clock change. Fix: the bar tells the sensors the clock changed when the setting or the OS regional format (`WM_SETTINGCHANGE` "intl") changes, and refreshes its own numbers.
- [ ] **Low — graph grid lines are 2 physical px at 150 % and more.** `common/graph.rs` `hairline`. Fix: `1 / scale`.
- [ ] **Low — the dual graph's halves differ by a pixel.** `common/dual_graph.rs` `halves`: 11.5 px halves snap to 12 and 11 px. Fix: whole-pixel halves, the remainder to the gap.
- [ ] **Low — a fractional `interval` or `width` makes a placeholder.** The schema accepts `2.5` for an interval or `57.5` for a width, but the typed props are integers, so `create` fails. Fix: `schema::check` rounds intervals to whole seconds and sliders to their step.
- [ ] **Low — idle work in sensors.** The Memory and Swap meters compare raw bytes, so they redraw every sample although the shown percent is unchanged; graphs and meters lay out their unchanging label and reserve on every sample. Fix: compare what is shown; keep the reserve and label layouts per theme.
- [ ] **Low — `percent(-0.0)` prints `-0%`.** `format.rs`. Fix: normalise negative zero.
- [ ] **Low — click lines in the Disk, Date and Time hints.** §9's conventions add them "per §6.1", the hint examples of §9.4, §9.5 and §9.12 show none. Fix: the spec says the examples are complete: those hints have no click line.

## S15e — Bar and Settings

- [ ] **Medium — the picker no longer fits the window.** `ui/settings.slint` picker page: 14 types and 4 headings scroll the whole page, so Add and Cancel and the search box scroll away, and Up/Down move the selection out of view. Fix: only the list scrolls, and it follows the selection.
- [ ] **Low — the open hint is rebuilt whenever any sensor changes.** `bar/thread.rs` `refresh_hint`: an open calendar is laid out again every second because the CPU graph changed; `refresh_theme` resolves the theme for every queued sample. Fix: refresh the hint only when its sensor changed; resolve the theme only when settings or appearance changed.
- [ ] **Low — Date and Time are empty for a frame after being re-created.** `bar/sensors.rs` `sync`: a new clock shows nothing until its first wake-up, which comes after the next paint, so the right zone shifts and back on each preview edit. Fix: wake new sensors that are due before painting.
- [ ] **Low — a renamed adapter shows as Automatic.** `settings/form.rs` matches the stored `{ id, name }` exactly; a connection renamed since (same id) matches nothing and is not listed as missing. Fix: match by id.
- [ ] **Low — choice controls drop the stored value once another is chosen.** `form.rs` `drives`, `cpu_series`, `adapters` list an unavailable stored value only while it is the current one; a present optical drive stored for a Disk Meter is labelled "not connected". Fix: list the value stored when the form opened; name a present optical drive by its kind.
- [ ] **Low — `cpu_series` overflows on `core4294967295`.** `form.rs`: `i + 1` panics in debug builds. Fix: saturating arithmetic.
