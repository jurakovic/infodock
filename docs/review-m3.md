# M3 review findings

From the M3 close-out review (three clean-context reviewers on `86f5994..59b84b8`, 2026-10-15: platform, providers and sampler; sensors; bar, drag & drop and Settings). Findings marked *(to verify)* could not be checked without Windows hardware. Each group is one plan item (S15c–S15e); tick the finding here when it is fixed, with the commit.

## S15c — Drag & drop

- [x] **High — a move drop can let the source delete the originals.** *Fixed in `7e0e380`: `report_optimized_move`, `DROPEFFECT_NONE` from `Drop`; a Windows test reads the effects back.* `platform/windows/droptarget.rs` `Drop` answers `DROPEFFECT_MOVE` for the Folder Menu's moves and the Recycle Bin, which do the move themselves. By the shell's convention ("Handling Optimized Move Operations"), a source that gets `DROPEFFECT_MOVE` (and `CFSTR_PERFORMEDDROPEFFECT` = move) deletes its originals, racing our `IFileOperation`, and a recycle could end as a permanent delete. Fix: after a move drop, set `CFSTR_PERFORMEDDROPEFFECT` to `DROPEFFECT_NONE` (and `CFSTR_LOGICALPERFORMEDDROPEFFECT` to move) and answer `DROPEFFECT_NONE` from `Drop`; the pointer during the drag still shows the move.
- [x] **Medium — file-system calls on the bar thread during a drag.** *Fixed in `7e0e380`: `Dropped::Path`, `path_kind` at a drop that makes sensors; `volume_of` by roots.* `bar/thread.rs` `drag_enter` calls `path_kind` for every item, and the Folder Menu's `drop_plan` calls `volume_of` (`GetVolumePathNameW`) for the folder and every item, inside OLE's synchronous callbacks. Thousands of items, or items or a folder on a slow share, freeze the bar and Explorer's drag. Fix: classify paths only by form while dragging (file or folder is asked only at a drop that makes new sensors); compare volumes by their roots (drive letter or share), so a drag touches no drive.
- [x] **Medium — adding a Disk lists every volume on the bar thread.** *Fixed in `7e0e380`: `with_machine_props` skips fields the changes set.* `sensors/ops.rs` `with_machine_props` fills machine-derived fields before applying the given props, so a dropped drive (and a Disk added from the menu) calls `DiskType::machine_defaults` → `volumes()` inside `Drop`. Fix: fill only the machine fields the given props leave unset.
- [x] **Low — a malformed `Shell IDList Array` can read past the buffer.** *Fixed in `7e0e380`: `drag::id_list_fits`.* `droptarget.rs` `shell_id_paths` checks two bytes at each offset before `ILCombine` walks the ID list. Fix: walk each list's `cb` chain inside the bytes and require its terminator first.
- [x] **Low — a dragged URL can add keys to a `.url` file.** *Fixed in `7e0e380`: `is_web` refuses control characters.* `bar/drop.rs` `is_web` checks the prefix only; a CR/LF inside the URL adds lines such as `IconFile=\\host\share\x.ico`, which Explorer fetches. Fix: refuse addresses with control characters.

## S15d — Platform and providers

- [ ] **Medium — one stalled key holds up a reader's other keys.** `providers/worker.rs`: each reader has one worker taking keys in order, and `sample` waits 200 ms for a key that was already stuck at the previous tick. A Disk Meter on a mapped drive whose server is away freezes the other drives' readings and costs the sampler 200 ms per stuck key per tick. Fix: one worker per key; wait only for a reading asked for in this call.
- [ ] **Medium — a reading that comes after the wait is used only at the next tick.** `worker.rs`, `sampler/mod.rs`: a drive plugged in whose listing takes longer than 200 ms appears only at the next 60 s `volumes` tick; the same for the Recycle Bin after emptying and batteries after a power change. Fix: a late answer reports a change for its reader's topics, which are read at once and take the answer without asking again.
- [ ] **Medium — Eject vetoes are judged by the name's form** *(to verify)*. `platform/windows/eject.rs` `request_eject`: for the usual vetoes (`PNP_VetoOutstandingOpen`, `PNP_VetoDevice`) the name is a device instance path (`STORAGE\Volume\{…}`), shown as the program; an app's veto (`PNP_VetoWindowsApp`) is an NT path to its module, thrown away; other vetoes become "in use" and skip the shell fallback. Fix: decide by veto type: an app → its module's file name, a service → its name, open handles and devices → in use without a name, anything else → failed, with the fallback.
- [ ] **Medium — Eject can climb past the storage device into a hub or dock** *(to verify)*. `eject.rs` `removable_above` ejects the first removable node within eight levels; for a card reader built into a dock whose port is not removable, that is the dock's hub (keyboard, network and all). Fix: stop at the first USB device above the disk; if it is not removable, eject only the medium.
- [ ] **Medium — an eMMC system disk can be ejectable** *(to verify)*. `device.rs` `on_removable_bus`: cheap laptops put the system disk on an SD or MMC bus, so C: shows in Eject USB and the Disk offers *Eject*. Fix: never mark the Windows drive ejectable, and for SD and MMC also require removable media.
- [ ] **Low — Sleep and Hibernate do not enable the shutdown privilege** *(to verify)*. `power.rs`: `SetSuspendState` needs `SeShutdownPrivilege`, which a standard token has disabled. Fix: enable it first, as for shut down.
- [ ] **Low — media ejection does not clear a media lock** *(to verify)*. `eject.rs` `eject_media`. Fix: send `IOCTL_STORAGE_MEDIA_REMOVAL` with removal allowed before ejecting.

## S15e — Sensors and bar

- [ ] **Medium — the width grip jumps when the popup's alignment flips while resizing.** `common/folder_browser.rs` `drag`/`grab` read `cx.free_left` on every move, and the bar recomputes it from each new size: widening a left-aligned list until it no longer fits flips it right-aligned, and the next move reads the other edge, so the width bounces to 130 and can be saved so. Fix: the bar keeps the alignment while the popup captures the pointer.
- [ ] **Medium — the unplug alert repeats when charging flaps.** `battery.rs`: `alerted` (and the time-to-full estimate) is reset whenever the state is not *Charging*, so 99 % ↔ 100 % (or Windows' charging ↔ not charging near full) toasts again each time. Fix: reset them when the charger is unplugged.
- [ ] **Medium — the 6 GHz channel underflows.** `wifi.rs` `band_channel`: 5926–5949 MHz (6 GHz channel 2 is 5935) subtracts 5950 from a smaller `u32`: a panic in debug builds, a huge channel in release. Fix: channel 2 by its frequency, the formula from 5950.
- [ ] **Medium — a long folder floods the icon worker and evicts the bar's icons.** `bar/icons.rs`: scrolling a large folder asks for every row's icon in turn, queued first in, first out, and at 256 entries the cache drops every ready icon, the bar's Shortcuts and Disks too, which then measure as *loading* and blink. Fix: evict the least recently asked-for icons only, beyond what the bar shows.
- [ ] **Low — the eject list marks rows by position.** `common/eject_list.rs`: after a drive leaves the list, the marked button (and a press held across a refresh) is the next drive's. Fix: targets name their drive.
- [ ] **Low — eject-list sizes are kept by root.** A new stick in the same letter shows the old size; a failed read is not retried. Fix: key sizes by root and label, and drop failed ones on refresh.
- [ ] **Low — a Shortcut reads its icon twice at start.** `shortcut.rs` `on_sample` refreshes the icon when the first `path` sample arrives. Fix: refresh only when a known kind changes (as the Disk does).
- [ ] **Low — *Low Battery* compares the unrounded percentage.** `battery.rs` (§9.14 compares whole percentages). Fix: round first.
- [ ] **Low — a power mode this computer lacks clicks into a failure.** `power.rs`: a config from another machine with *Hibernate*. Fix: the hint says it is not available here and the click does nothing.
- [ ] **Low — an open popup survives hiding the bar with the hotkey.** `bar/mod.rs` `set_visible`: the popup stays over the screen pointing at nothing. Fix: hiding the bar closes the popup and the hint.
- [ ] **Low — the hint comes back over the sensor whose popup just closed.** `bar/thread.rs`: a pointer move while the popup is open clears the hint's dismissal. Fix: no hover tracking while a popup is open.
- [ ] **Low — a slow click on the popup's own sensor reopens it.** `bar/thread.rs`: the 500 ms guard runs from the press that closed the popup, so releasing later opens it again. Fix: the press that closed a sensor's popup never opens it.

## Not changed

- **Shortcut clicked before its first sample** (`shortcut.rs`): a folder target with parameters or *Run as administrator* is launched as a program until the first `path` sample (normally within the first second). Left as is.
- **Popup that cannot take the foreground** *(to verify)* (`platform/windows/popup.rs`): if Windows refuses the activation, the popup closes only on Esc after a click, a second click or a bar press. To check on hardware in the M3 manual test; a foreground hook if it happens.
- **Battery positions** (`platform/windows/battery.rs`): a battery that fails to read drops out and the next takes its index. Two-battery laptops are rare; revisit with the M5 reliability pass.
- **Settings reads batteries and volumes on the main thread** (`settings/properties.rs`): as in M2, while a form with those fields opens; the forms take the sampler's samples in M5.
- **Wi-Fi capability fixed at start-up**: as §4.6 says; an adapter turned on later is found at the next start.
- **Folder Menu's folder is not required in Properties**: the sensor says *No folder set* and does nothing; a required-field rule comes with the M4 form work.
