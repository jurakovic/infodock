# M1 review findings

From the M1 close-out review (four clean-context reviewers, 2026-10-12). High and medium findings were checked against the code; low ones are consistent with it, and those marked *(to reproduce)* still need a reproduction. Line numbers are as of commit `7f85ea4`. Each group is one plan item (S12a–S12e); tick the finding here when it is fixed, with the commit.

## S12a — Settings: input that is lost or saved wrongly

- [x] **High — hotkey recording survives a page change.** *Fixed in `dcb0dd5`: the page change ends recording, and keys count only on General.* `src/settings/mod.rs` page-changed handler (≈154) and `record_hotkey` (≈399). Click the hotkey button, go to another page and type: every key is swallowed, and e.g. Ctrl+V gets registered and saved as the global hotkey. Fix: clear `recording-hotkey` when the page changes (and/or ignore keys unless page 0).
- [x] **High — typed paths and colours are lost on Save or navigation.** *Fixed in `dcb0dd5`: path rows commit on `edited`, colours once the text is a colour; a page change refills from the config.* `ui/settings.slint` path box (≈1139), `ColorField` (≈277–302); `src/settings/properties.rs` `save`. They commit only on Enter or focus-out, and Fluent buttons and the navigation list do not take focus (their FocusScope is 0 px wide), so typing a path and clicking Save saves the old value; a colour typed on Popups and left by the navigation is shown but never saved. Fix: commit path rows on `edited`; commit colours on `edited` once the text is a valid `#RRGGBB`, or flush pending text before save/page change.
- [x] **Medium — focus-out and slider clicks pin theme defaults.** *Fixed in `024a8b3`: colour and number changes are saved only when the value in effect changes (`model::changes`).* `ColorField` saves on every focus-out; `ValueSlider` sends `released` on a click without movement (`src/settings/mod.rs` `on_set_color` ≈198, `on_set_number`). Tabbing through Popups ▸ Background turns `null` into `"#202024"` (§11.2). Fix: skip the save when the normalised value equals the value in effect (or emit only on change).
- [x] **Low — Browse does not show the picked path after typing.** *Fixed in `46e2d81`: the row is replaced, which builds a new box.* `src/settings/properties.rs` `browse` (≈233); `text: row.text` is one-way and typing breaks it, so the box keeps the typed text and the next focus-out undoes the pick. Fix: two-way bind to a per-row value, or recreate the row.
- [x] **Low — slider shows an unsaved value.** *Fixed in `46e2d81`: the label rounds to the step and the slider snaps to it on release.* `ValueSlider` (`ui/settings.slint` ≈234): the label shows the raw dragged value while the saved one is rounded to `step` (612 ms shown, 600 saved). Fix: round `root.value` on release.
- [x] **Low — stale hotkey error** *(to reproduce)*. *Fixed in `46e2d81`: `hotkey::set` keeps an error only for the configured hotkey.* `src/hotkey.rs` `set` (≈124): a refused combination's error is stored and shown after reopening Settings although the configured hotkey works. Fix: store the error only for the configured accelerator.
- [x] **Low — Ctrl+Space in the navigation blanks the page** *(reproduced in the render test)*. *Fixed in `46e2d81`: the navigation goes back to the page shown.* `StandardListView` can set `current-item` to −1, so `page` becomes −1. Fix: restore the previous page when it is below 0.

## S12b — Settings: validation and keyboard

- [x] **Medium — properties validation differs from §6.7.** *Fixed in `16d5167`: invalid fields are tracked (`Form::valid`), the row shows the error, Save is disabled; colour boxes in the form report every edit.* `src/settings/properties.rs` `edit` (≈122): one page-level error that the next valid edit clears, and Save is never disabled, so `#12345` can stay in the box while the old colour is saved. Fix: track invalid keys in `FormState`, show the error on the row, disable Save while any is invalid.
- [x] **Medium — the Layout manager loses keyboard focus after each change.** *Fixed in `16d5167`: the list is rebuilt only when a line changed; the moved sensor's button takes the focus again (`layout-focus-id`).* `src/settings/layout.rs` `fill` installs a new `VecModel` on every config change, so the Repeater rebuilds every row. Fix: update the model in place, and refocus the moved row's button (e.g. a `layout-focus-id`).
- [x] **Medium — the sensor picker cannot be used from the keyboard.** *Fixed in `16d5167`: a search selects the first match, Up/Down in the search box move the selection.* `ui/settings.slint` `PickerPage`: rows cannot take focus, no arrow keys, Enter adds only with a selection. Fix: select the first match when nothing is selected, and move the selection with Up/Down in the search box.

## S12c — Bar

- [x] **Medium — Sensor spacing does not re-space the bar.** *Fixed in `c4b4b50`: `BarSensors` remembers the spacing it placed with.* `src/bar/sensors.rs` `invalidate_all` (≈138) / `update_layout` (≈146): a theme change marks sensors dirty but does not set `relayout`; equal widths mean no re-placing, and the drag placer uses the new gap with old positions. Fix: remember the last `(pad, gap)` and re-place when they differ (or set `relayout` in `invalidate_all`).
- [x] **Medium — the bar can stay invisible after an aborted slide-out.** *Fixed in `c4b4b50`: already placed at the edge it docks to, it rises at once.* `src/bar/thread.rs` `frame` (≈385) with `appbar.rs` `place` (≈242): `Placed` is emitted only when request or rect changed, so changing the edge and back within 300 ms (or another `apply` during the slide) leaves `shown` at 0: transparent content that still reserves space and takes clicks. Fix: make the redock always lead to a rise (force a `Placed`, or call `rise()` when the placement is unchanged).
- [x] **Low — every animation frame repositions the window.** *Fixed in `c4b4b50`: slides only on a new offset; the AppBar keeps the offset through an unchanged placement.* `frame` calls `slide(dy)` even when `dy` is unchanged (e.g. highlight-only frames): a `SetWindowPos` plus a cross-process `ABM_WINDOWPOSCHANGED` each. Also `place` ignores the slide offset, so a reposition mid-rise jumps the window for a frame. Fix: slide only when `dy` changes; keep the offset in the AppBar state and re-apply it in `place`.
- [x] **Low — `animations: auto` does not follow the OS live.** *Fixed in `c4b4b50`.* `src/platform/windows/window.rs` (≈239): `AppearanceChanged` is raised only for `ImmersiveColorSet`; toggling Animation effects sends `WM_SETTINGCHANGE` with `SPI_SETCLIENTAREAANIMATION`. Fix: dispatch `AppearanceChanged` for that wParam too.
- [x] **Low — a failed frame is not redrawn** *(to reproduce)*. *Fixed in `c4b4b50`: a retry timer (250 ms) redraws it.* `window.rs` render path (≈338): `repaint` is only read at the end of the next dispatch, so with no timers the bar keeps a stale frame. Fix: post an invalidate (or arm a short timer) after a failed render.
- [x] **Low — a live hint is anchored to the old layout.** *Fixed in `c4b4b50`: `BarSensors::refresh_layout` before the hint is placed.* `src/bar/thread.rs` (≈732, ≈759): `refresh_hint` runs before dirty sensors are measured and placed (that happens in paint). Fix: refresh the shown hint after layout.
- [x] **Low — hairline uses the configured edge.** *Fixed in `c4b4b50`.* `src/bar/thread.rs` `paint` (≈879) uses `settings.bar.edge`; a floating bar near the top, and a bar sliding out, get it on the wrong side (§12.2). Fix: use `geometry.edge`, falling back to the setting.
- [x] **Low — floating bar picks the monitor by its top-left corner.** *Fixed in `c4b4b50`: the largest share, compared at each monitor's scale, in `i64`.* `src/platform/geometry.rs` `floating_rect` / `monitor_at` (≈160, ≈184): a bar dropped mostly on monitor B with its left edge on A snaps back to A; `b.left - x` can overflow `i32` for extreme hand-edited values. Fix: choose the monitor with the largest intersection (or containing the centre), compute in `i64`.

## S12d — Images

- [x] **High — SVG decoding has no resource limits.** *Fixed in `7136d64`: embedded rasters above 16 MP are skipped, `.svgz` (outer and embedded) is inflated with a 32 MB cap.* `src/platform/bitmap.rs` `render_svg` (≈194): embedded `data:` rasters are decoded at their declared size (a tiny SVG claiming a 1,000,000² PNG aborts the process, on every start since the path is saved), and gzip (`.svgz`) is inflated without a cap. Fix: wrap `image_href_resolver.resolve_data` to refuse rasters above `MAX_SIDE` (or all embedded rasters); inflate gzip with a `take(LIMIT)` and parse the text.
- [x] **Low — size limits check the source, not the output.** *Fixed in `7136d64`: SVG checks the result only; raster sources are capped at 64 MP (`raster_size`).* `scaled_size` (≈180): an SVG with a huge `viewBox` is refused though it renders small; a 65,536² compressible PNG under 32 MB is accepted and decoded synchronously on the bar thread. Fix: for SVG check only the output; for rasters cap the source pixel count (e.g. 64 MP).
- [x] **Low — third-party WIC decoders can be picked.** *Fixed in `7136d64`: `CreateDecoder` with the container GUID and `GUID_VendorMicrosoftBuiltIn`.* `src/platform/windows/image.rs` (≈102) `CreateDecoderFromStream` with no vendor, against §4.6. Fix: `CreateDecoder` with the sniffed container GUID and `GUID_VendorMicrosoftBuiltIn`, then `Initialize`.
- [x] **Low — images are blurry at 125 % and 150 %.** *Fixed in `7136d64`: the origin is snapped.* `src/sensors/image.rs` `draw` (≈160) draws at an unsnapped logical x (7 px pad → 10.5 physical px) with linear filtering. Fix: snap the destination origin (`canvas.snap`), in the sensor or in `draw_bitmap`.

## S12e — Sensor framework (needed before M2)

- [ ] **Medium — `add` stores static defaults for machine-derived fields.** `src/sensors/ops.rs` `add` (≈37) with `schema.rs` `to_stored` (≈308): `updated_props` resolves with no machine values and `to_stored` keeps machine fields, so `fill_machine_props` finds nothing missing (a Time sensor would get 24 h whatever the locale). Same for `update`/`preview` of an instance lacking a machine field. Fix: call `fill_machine_props` before `updated_props`; add an ops test with a fixture type that has a `.machine()` field.
- [ ] **Medium — a re-created sensor gets no catch-up sample.** `src/sampler/scheduler.rs` `subscribe` (`fresh`, ≈68) and `src/bar/thread.rs` `sync_sensors` / `subscription_changes`: a sensor re-created after a preview or props change keeps its id and topics, so nothing is re-sent and nothing caught up; a sample in the same wake batch goes to the old instance. Fix: have `BarSensors::sync` report created ids and re-subscribe those; let the scheduler send the newest sample on every subscribe; optionally sync before handling queued samples.
- [ ] **Low — a failed start can lose its log line.** `src/lib.rs` (≈74): when Slint's backend cannot start, `run()` returns without `store.shutdown()` / `logging::shutdown()`. Fix: shut both down on that path.
